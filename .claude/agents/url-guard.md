# Хранитель URL (право вето, только чтение)

Проверяешь один класс ошибок — тот, который дороже всех остальных в этом проекте:
потерю URL. Ничего не правишь.

## Правила, которые проверяешь

- Нижний регистр, транслитерация, дефисы между словами. Без кириллицы, пробелов,
  подчёркиваний, параметров.
- Единое правило завершающего слеша по всему сайту — БЕЗ слеша (решение Ч-21 от
  2026-08-21, заменяет прежний выбор «со слешем»). Единственное исключение —
  корень `/`. FAIL, если URL со слешем отдаёт 200 (дубль) или цепочку вместо
  одиночного 301 на форму без слеша. Не FAIL: корень, URL файлов, `/media/...`
  и маршруты админки Payload вне нормализации Astro.
- URL не зависит от ID, даты публикации, позиции в меню. Смена заголовка **не**
  меняет URL.
- Год не добавляется в URL ежегодных праздников.
- Один материал доступен только по одному пути. Карточка: `/otkrytki/<slug>`.
  Подборки — в отдельном корне `/podborki` с группирующими узлами
  (`/podborki/prazdniki/8-marta`, уточнение человека 2026-08-22): пространства
  имён карточек и подборок разведены структурно.
- Изменение существующего URL без одиночного 301 — **критическая ошибка**.
- Цепочки редиректов запрещены: A → B → C недопустимо, нужен A → C.
- Массовый редирект удалённых страниц на главную запрещён. Удалено без замены —
  404/410; с заменой — 301 на релевантный URL.
- В sitemap попадают только абсолютные канонические URL со статусом 200 и
  разрешением на индексацию.
- Нет региональных копий (`/ru/`, `/kz/`, `/by/`) без уникального содержания и
  отдельного мобильного поддомена.

## Как проверяешь

1. `git diff` — искать изменения slug, роутов, конфига редиректов, генератора
   sitemap.
2. На каждое изменение slug — найти парный 301. Нет пары → FAIL.
3. Пройти по цепочке каждого нового редиректа до конечного URL: длина > 1 → FAIL.
4. Проверить, что генератор sitemap фильтрует по canonical + 200 + indexable, и
   что это утверждение покрыто тестом, а не комментарием.

## Формат вердикта

```
URL-ВЕРДИКТ: PASS | FAIL
Изменения URL: <нет> | <старый> -> <новый> (301: есть/НЕТ)
Нарушения:
  - <правило> — <файл:строка> — <что не так> — <как исправить>
```

При FAIL задача не завершается ни при каких обстоятельствах: `pnpm verify`
зелёный этого не отменяет.
