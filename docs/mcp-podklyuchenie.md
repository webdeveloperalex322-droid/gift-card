# Подключение внешней LLM к каталогу через MCP

Операционная инструкция к ручке `POST /api/mcp` (решение Ч-35). Устройство и
обоснование решений — в `docs/superpowers/specs/2026-10-03-mcp-vneshniy-redaktor-design.md`,
код — в `apps/cms/src/mcp/`.

Граница автоматизации не обсуждается и каналом не сдвигается: внешняя модель
доводит контент до `review`. Публикация и `index,follow` — решение человека с
ролью `admin` (п. 7.1 и п. 23 ТЗ, Ч-07).

## Что должно быть сделано на сервере

Ручка работает, когда выполнены оба условия. Любое невыполненное даёт отказ,
который легко принять за поломку клиента.

1. **`MCP_ENABLED=true`** в `~/otkritka/otkritka.prod.env`, и переменные
   проброшены в контейнер `cms` (`deploy/docker-compose.prod.yml`). Пустое
   значение = выключено, ручка отдаёт `404` и своего существования не
   подтверждает. Любое значение кроме `true`/`false` валит старт `cms` — это
   намеренно: «включено» не должно получаться опечаткой.
2. **Локация nginx со снятым Basic Auth.** Весь сайт на проде закрыт
   `auth_basic` на `server`-блоке, а клиент не может предъявить одновременно
   Basic и собственный Bearer: заголовок `Authorization` один. Поэтому в
   `/etc/nginx/sites-available/otkritka` перед `location /admin {` нужны две
   точечные локации:

   ```nginx
   location = /api/mcp {
       auth_basic off;
       proxy_pass http://127.0.0.1:3011;
       include /etc/nginx/snippets/otkritka-proxy.conf;
   }
   location = /api/mcp/ {
       auth_basic off;
       proxy_pass http://127.0.0.1:3011;
       include /etc/nginx/snippets/otkritka-proxy.conf;
   }
   ```

   Затем `sudo nginx -t && sudo systemctl reload nginx`.

   **Это исключение из Ч-18, выведенное агентом как следствие Ч-35d, а не
   решение человека.** Ч-18 требует Basic Auth на обратном прокси; строки,
   разрешающей снять его с какого-либо адреса, в реестре нет. Довод — заголовок
   `Authorization` один, и Basic его занимает (см. абзац «Запись состояния, а не
   решение» при строке Ч-35). Накатывает локацию человек своим действием; хотите
   отказаться от исключения — MCP снаружи не работает, и это допустимый выбор.

   **Совпадение точное (`=`), а не префиксное.** `^~ /api/mcp` сняло бы Basic
   Auth и с `/api/mcpx`, и с `/api/mcp/<что угодно>`, то есть с будущей
   коллекции, чьё имя начинается на `mcp`. Это единственное снятие Basic Auth во
   всей конфигурации, кроме ACME-челленджа.

   **Репозиторный `deploy/nginx/dobrye-otkrytki.ru.conf` целиком на сервер не
   копируется.** Живой vhost отстаёт от него: в репозитории Basic Auth оставлен
   только на `/admin`, `/api` и `/_next`, а `location /` открыт — правка
   коммита `43e2ccf` от 2026-10-03, на сервер не накатанная. **Провенанс этой
   правки не закрыт:** шапка файла ссылается на решение человека от 2026-10-02,
   но строки о снятии Basic Auth с публичной части в реестре решений нет, а
   Ч-34 упоминает ту же правку как незадеплоенную, без ссылки на решение.
   Перезапись живого файла репозиторным открыла бы публичную часть сайта наружу
   одной операцией, в том числе шесть узлов, открытых в `index,follow` по Ч-34.
   Это отдельное решение человека, а не побочный эффект включения MCP, и до него
   правьте живой vhost точечно — локациями выше, а не копированием файла.

## Токен

Токен — **API-ключ аккаунта `ai-editor`**, а не отдельный секрет в env и не
третий аккаунт (Ч-35f, Ч-16). Где взять: админка → `Users` → `ai-editor` →
включить `Enable API Key` → скопировать значение.

- Схема — `Authorization: Bearer <ключ>`, **не** формат Payload
  `Authorization: users API-Key <ключ>`.
- Ключ аккаунта с другой ролью, включая `admin`, каналом не принимается.
  Расширение требует отдельного решения человека.
- Отзыв ключа кнопкой в админке выключает и MCP: сверх поиска по отпечатку
  проверяется флаг `enableAPIKey`, которого своя стратегия Payload не смотрит.
- Предел частоты Ч-14 (60 запросов в минуту, всплеск 120) действует на ключ, и
  MCP с прямым REST по одному ключу делят один бакет.

Ключ — секрет уровня «правка контента на проде». В репозиторий, в тикеты и в
логи он не попадает.

## Проверка руками

```bash
curl -sS -X POST https://dobrye-otkrytki.ru/api/mcp \
  -H 'Authorization: Bearer <ключ>' \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Ожидается JSON-RPC-ответ со списком инструментов. Запрос без `_meta` и без
заголовка версии обслуживается как legacy-клиент ревизии `2025-03-26` — именно
так ходят сегодняшние CLI, поэтому рукопожатие `initialize` для пробы не нужно.

## Настройка клиентов

**Claude Code** (сверься с `claude mcp add --help`, синтаксис флагов меняется):

```bash
claude mcp add --transport http otkritka https://dobrye-otkrytki.ru/api/mcp \
  --header "Authorization: Bearer <ключ>"
```

**Gemini / Antigravity CLI** — в `settings.json`:

```json
{
  "mcpServers": {
    "otkritka": {
      "httpUrl": "https://dobrye-otkrytki.ru/api/mcp",
      "headers": { "Authorization": "Bearer <ключ>" }
    }
  }
}
```

**ChatGPT не подключается** (Ч-35d). Для удалённого MCP он принимает только
пользовательский OAuth 2.1 либо «без аутентификации»; API-ключей и своих
заголовков не поддерживает, а «без аутентификации» для пишущей в прод ручки
неприменимо. OAuth — отдельный этап.

## Инструменты

Чтение:

| Инструмент | Что делает |
|---|---|
| `catalog_overview` | дерево подборок, число опубликованных открыток, нехватка до порога Ч-06 |
| `collection_get` | одна подборка целиком |
| `card_get` | одна карточка целиком |
| `find_weak_content` | незаполненные и повторяющиеся title/description, карточки без изображения, без alt, без привязки к подборкам |
| `check_duplicates` | совпадения title и description **по всему каталогу**, а не по окну выборки |

Запись:

| Инструмент | Что делает |
|---|---|
| `create_card_draft` | карточка в `draft` + `noindex`; идемпотентен по slug |
| `update_card_text` | тексты, метатеги, alt карточки |
| `attach_card_to_collections` | добавляет привязки, не заменяя существующие |
| `detach_card_from_collections` | убирает привязки |
| `attach_image` | привязывает **уже загруженное** изображение по id |
| `create_collection_draft` | подборка в `draft`; идемпотентен по паре slug + родитель |
| `update_collection_text` | тексты и метатеги подборки |
| `send_to_review` | `draft` → `review`; полноту проверяет хук Payload |

**Байты изображений через MCP не передаются** (Ч-35c): файлы грузятся скриптами
импорта или руками в админке, MCP только привязывает их по id.

**Ничем не умеет:** публикацию, `index/noindex`, canonical, смену slug после
публикации, редиректы, sitemap, пользователей и ключи. Инструментов нет, и
отдельно запрещает access control — то есть запрет держится даже если
инструмент однажды появится по ошибке.

**Ответ честный.** После записи запись перечитывается и сверяется с
запрошенным. У Payload отказ на уровне поля молчаливый: поле вырезается из
входных данных, прежнее значение остаётся, ответ 200. Поэтому непустой список
`ignored` возвращается как ошибка инструмента, а не как успех с оговоркой —
иначе модель отрапортовала бы человеку о несделанном.

## Разбор отказов

| Что видно | Причина |
|---|---|
| `401` с `WWW-Authenticate: Basic realm="otkritka (closed)"` | локации nginx нет, запрос съел Basic Auth |
| `404` с телом `{"errors":[{"message":"Not Found"}]}` | `MCP_ENABLED` не `true` в контейнере `cms`, либо образ собран без MCP-слоя. Выключенная ручка намеренно не подтверждает своего существования |
| `404` с JSON-RPC-ошибкой `-32601` | ручка жива, но метод или имя инструмента не существуют — обычно опечатка. В сообщении перечислены доступные методы либо названо несуществующее имя инструмента |
| `401` с JSON-RPC-телом про API-ключ | ключ не предъявлен, отозван, не существует или принадлежит аккаунту не с ролью `ai-editor`. Текст один на все причины намеренно: подробность отказа помогала бы перебору |
| `405` с `Allow: POST` | метод не POST. Ручка принимает только POST |
| `403` | предъявлен `Origin`, которого нет в `MCP_ALLOWED_ORIGINS` (защита от DNS rebinding). Пустой список означает, что любой присланный `Origin` отвергается, а запрос без `Origin` проходит |
| `429` с `Retry-After` | предел Ч-14 на ключ, либо отдельный предел неудачных попыток аутентификации на адрес |
| `-32020` HeaderMismatch | заголовок `Mcp-Method`/`Mcp-Name`/`MCP-Protocol-Version` расходится с телом. Тело — источник правды, расхождение обязано отвергаться |
| `-32022` с `data.supported` | версия протокола не обслуживается; в `data.supported` список поддерживаемых |
| `isError` с непустым `ignored` | access control отказал в части полей. Смотри, что именно перечислено: обычно это попытка записать поле, закрытое для роли `ai-editor` |

## Аудит

Каждая правка попадает в `seo-history` с автором, его ролью и признаком
`viaApiKey` — то есть шаг внешней модели отличим от правки человека из админки и
прослеживаем.
