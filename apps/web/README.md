# apps/web — Astro

Владелец: агент `astro-web`.

Установлено на задаче Э3-01: astro 7.2.4 + @astrojs/node 11.1.4 (`mode: 'standalone'`).

## Режим рендеринга

«Гибридный режим» отдельным значением `output` в astro 7 не выражается — в типе
конфига остались `'static'` и `'server'`. Актуальная форма гибрида: `output:
'static'` вместе с адаптером, а маршрут, которому нужен SSR, объявляет
`export const prerender = false`. Выбор и его обоснование зафиксированы
комментарием в `astro.config.mjs`.

## Правило завершающего слеша (решение Ч-21)

Единая форма — БЕЗ завершающего слеша. Правило живёт в ОДНОМ месте:

- `src/routing/path-policy.ts` — чистая функция `decideRequestPath`: рендерить,
  отдать одиночный 301, ответить 404 или не вмешиваться (маршруты админки);
- `src/middleware.ts` — тонкая обёртка, превращающая решение в HTTP-ответ.

Границу «страница или файл» даёт `isPageRoute` из `@otkritka/shared`, форму пути
— `canonicalizePath` оттуда же. Локальных копий этих правил здесь нет и быть не
должно.

Проверки:

```bash
pnpm exec vitest run tests/unit/web-path-policy.test.ts   # решение по пути
pnpm --filter @otkritka/web run build
pnpm --filter @otkritka/web run smoke:slash               # 301 и отсутствие цепочки на живом сервере
```

### Известные особенности окружения (замерено на astro 7.2.4)

- **Приёмку SEO гонять только против СОБРАННОГО сервера.** В `astro dev` при
  `trailingSlash: 'never'` Astro вместо 301 показывает страницу-предупреждение со
  статусом 404 (его документированное поведение, `config.d.ts`, раздел
  trailingSlash). Проверять правило слеша на dev-сервере нельзя — spec упадёт на
  верном коде. Порядок: `astro build`, затем `astro preview` или
  `node dist/server/entry.mjs`.
- **Кто именно отвечает 301.** На собранном сервере на маршрутах страниц
  срабатывает встроенный обработчик Astro (он вызывается до пользовательского
  middleware). Наша цель редиректа совпадает с его целью байт в байт, поэтому
  ответ один и цепочки нет. Наш middleware отвечает там, где Astro не
  вмешивается: пути с ведущим двойным слешем и пути с пустым сегментом.
- **`localhost` на Windows.** Node привязывает `localhost` к IPv6-петле
  (`[::1]`), поэтому инструмент, который резолвит `localhost` в `127.0.0.1`,
  до сервера не доходит. Для детерминированного адреса: `astro dev --host
  127.0.0.1`, а для собранного сервера — `HOST=127.0.0.1`.

## Абсолютные URL

Только через `canonicalUrlFor` (`src/routing/canonical.ts`), а он — через
единственный хелпер `buildAbsoluteUrl` из `@otkritka/shared`. `site` в
`astro.config.mjs` НЕ задан намеренно: `Astro.site` стал бы вторым источником
хоста. Окружение читается в рантайме (`src/server-env.ts`), а не запекается в
сборку.

## Инварианты рендеринга (`CLAUDE.md`)

- title, H1, canonical, хлебные крошки, основной текст, ссылки и первые
  изображения — в HTML-ответе сервера; страница полноценна при отключённом JS;
- навигация только `<a href>`, hash-маршрутизация запрещена;
- клиентский JS — только точечные острова; в `BaseLayout.astro` его нет вовсе,
  панель разработчика Astro выключена в конфиге;
- пагинация с постоянными URL, бесконечная лента запрещена.
