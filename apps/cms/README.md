# apps/cms — Payload CMS

Владелец: агент `payload-cms`.

Payload ещё не установлен. Первая задача агента `payload-cms` — поставить Payload
на PostgreSQL и описать коллекции `cards`, `collections`, `redirects`,
`seo-history` по модели данных из `CLAUDE.md`.

Отдельный API-слой не пишется: Payload сам отдаёт REST и GraphQL. Поэтому все
защитные правила живут в серверных хуках и access control — так они действуют
одинаково для админки и для внешнего AI-редактора, и обойти их через API нельзя.

Обязательные инварианты:

- новая запись создаётся только в статусе `draft` с `noindex`;
- перевод в `published` и открытие в `index,follow` — действие человека с ролью
  `admin`, никогда не сервисного аккаунта `ai-editor` и никогда не автоматическое;
- `beforeChange`: slug неизменяем после первой публикации; смена URL возможна
  только с одновременным созданием 301-редиректа;
- `seo-history` фиксирует автора каждого изменения SEO-полей.
