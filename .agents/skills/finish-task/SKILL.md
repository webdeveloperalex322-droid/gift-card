# Протокол завершения задачи

Задача не считается выполненной, пока не пройдены все шаги по порядку. Каждый шаг
создаётся отдельным пунктом todo-списка.

## Шаг 1 — verify целиком

```bash
pnpm verify
```

Зелёный целиком, без исключений. Вывод сохраняется для отчёта. Красный verify —
задача не выполнена, независимо от того, насколько «мелкой» кажется правка.

Если `test:seo` вывел `SEO_ACCEPTANCE: SKIPPED` — это **не прохождение**. Статус
переносится в отчёт дословно вместе с причиной.

## Шаг 2 — SEO-замер до и после

Обязателен, если тронуты: шаблон страницы, роутинг, sitemap, robots, коллекции
Payload, вывод изображений.

```bash
pnpm test:seo   # до правки — базовый замер
pnpm test:seo   # после правки — дельта в отчёт
```

Базовый замер снимается **до** изменений. Забыли снять — снимите на
`git stash`, а не пишите «дельту не измеряли».

## Шаг 3 — вето контролёров

Вызываются через Agent tool. Вердикт FAIL блокирует завершение, даже если
`pnpm verify` зелёный.

| Что тронуто | Обязательный контролёр |
|---|---|
| slug, роут, canonical, редиректы, sitemap | `url-guard` |
| шаблон, роутинг, sitemap, коллекции, изображения | `seo-auditor` |
| любой диф | `reviewer` |

Контролёры только читают. Их находки исправляет агент-владелец слоя, после чего
шаги 1–3 повторяются.

## Шаг 4 — отчёт по шаблону

```markdown
## Что сделано
<1–3 строки: изменение и зачем>

## Файлы
- path/to/file.ts — что изменилось

## Проверка
- pnpm verify: PASSED | FAILED
- pnpm test:seo до: PASSED | FAILED | SKIPPED (<причина>)
- pnpm test:seo после: PASSED | FAILED | SKIPPED (<причина>)
- url-guard: PASS | FAIL | не требовался
- seo-auditor: PASS | FAIL | НЕ ПРОВЕРЕНО | не требовался
- reviewer: PASS | FAIL

## Статусы контента
- создано в draft: <список или «нет»>
- переведено в review: <список или «нет»>
- переведено в published: всегда «нет» — это решение человека

## Требует решения человека
- <публикация, открытие в index,follow, смена URL, спорное требование ТЗ>

## Не сделано
- <что осталось и почему>
```

Пустые разделы не удаляются: «нет» — это информация, отсутствие раздела —
неизвестность.

## Шаг 5 — коммит

Малый, оставляет проект в состоянии зелёного `pnpm verify`. Коммит-сообщение — на
обычном языке, без сокращений.

## Чего нельзя делать при завершении никогда

- Переводить контент в `published` или ставить `index,follow` — это осознанное
  действие человека, граница автоматизации зафиксирована ТЗ (п. 7.1, п. 23).
- Выдавать `SKIPPED` за `PASSED`.
- Писать «готово» без вывода verify.
- Закрывать задачу при FAIL от `url-guard` или `seo-auditor`.
- Расширять объём работы, чтобы «раз уж всё равно тут».
